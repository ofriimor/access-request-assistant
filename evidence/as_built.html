ארכיטקטורה

שבעת השלבים, הרכיב שמבצע כל אחד מהם והמקורות שהם נוגעים בהם. השלב באדום הוא היחיד שדורש אדם, וה־Tool באדום הוא היחיד שמשנה מצב.

רכיבים ו־Tools

כל קובץ אחראי על דבר אחד. ה־LLM אף פעם לא קורא ל־Tool ישירות: כל קריאה עוברת ב־Engine.call_tool, שבודק Allowlist וסכמה, מבצע Retry ורושם ל־Audit.

רכיבקובץאחריות
Schemasapp/schemas.pyחוזים לקלט, לפלט ה־LLM ולכל Tool. שדה לא מוכר נדחה.
LLMapp/llm.pyחילוץ שדות מהטקסט באמצעות Google Gemini API (gemini-3.5-flash-lite). הטקסט מוגדר כ־Untrusted, הפלט עובר Validation עם Retry אחד, ושגיאות HTTP זמניות מקבלות Retry מוגבל.
Guardapp/guard.pyהחלטה דטרמיניסטית: מותר, חסר מידע או חסום. כולל זיהוי Prompt Injection.
State machineapp/state.pyסטטוסים ומעברים מותרים בלבד. SQLite, כולל טבלת Idempotency.
Engineapp/engine.pyמנהל את שבעת השלבים, את שער האישור, את ה־Retry ואת האימות שאחרי הביצוע.
Auditapp/audit.pyיומן Append-only: כל שלב, קריאה ל־Tool, שגיאה, אישור וסטטוס.
Report, CLIapp/report.py, app/__main__.pyהמסמך הזה וממשק שורת הפקודה.
search_policiesקריאה

חיפוש TF-IDF בחמשת מסמכי ה־Policy. מחזיר מזהה מקור וציון.

read_policyקריאה

מחזיר את ה־Policy של מערכת. מערכת שאינה ברשימה הסגורה נדחית.

lookup_userקריאה

מחלקה, מנהל, סטטוס והרשאות. גם הפלט עובר Validation.

grant_accessכתיבה

רק אחרי אישור עם plan_hash תואם. ערך admin לא ניתן לביטוי בסכמה, ו־request_id קיים מחזיר את ההרשאה הקיימת.

עמידה בדרישות

שתים־עשרה הדרישות הטכניות מהמשימה, ואיפה כל אחת ממומשת.

דרישהמימוש
1✓קלט ו־ValidationJSON שנבדק מול AccessRequestInput. שגיאה מציינת את השדה, ולא נוצרת רשומה.
2✓שימוש ב־LLMGoogle Gemini API (gemini-3.5-flash-lite) מחלץ intent, מערכת, רמה, משך, הצדקה ופערים.
3✓Knowledge Retrieval5 מסמכי Policy, שלוש ההתאמות הטובות עם מזהה וציון.
4✓שני Tools לפחות3 לקריאה, 1 לכתיבה.
5✓StateSQLite: סטטוס, היסטוריה, החלטות, תוצאות Tools, אישור ואימות.
6✓Human-in-the-loopרק המנהל הישיר מאשר, והאישור קשור ל־plan_hash.
7✓SchemasValidation לפני ואחרי כל Tool. שגיאה עוצרת ב־FAILED_SAFE.
8✓IdempotencyID שנגזר מהתוכן, מפתח פעולה ייחודי ב־DB, ו־Tool שמחזיר הרשאה קיימת.
9✓Error Handlingעד 3 ניסיונות עם backoff לשגיאה זמנית, ואז עצירה בטוחה שאפשר להמשיך ממנה.
10✓Post-Action Verificationקריאה חוזרת מה־Directory וחמש בדיקות.
11✓Audit Trailruntime/audit.jsonl, ומוצג גם כאן.
12✓HTML As-Builtהמסמך הזה, שנוצר אוטומטית מהנתונים.

Design מול As-Built

כל מקום שבו המימוש שונה מה־Design שניתן, ולמה.

ב־Designמה מומשלמה
Plan: בניית תוכנית והחלטה על Tool, אפשר בעזרת LLMההחלטה בקוד דטרמיניסטי (Guard). ה־LLM משמש רק ל־Understand.החלטת הרשאה צריכה להיות צפויה, ניתנת לבדיקה וחסינה ל־Prompt Injection.
Approve: עצירה ואישור אנושיהאישור נשמר עם plan_hash, ורק המנהל הישיר מורשה. כשהמנהל הישיר הגיש את הבקשה, המנהל שלו מאשר. מאשר מושבת לא יכול לאשר.מונע מצב שבו מאשרים דבר אחד ומבצעים דבר אחר, ומונע מאדם לאשר בקשה של עצמו.
Execute: הפעלת Tool שמשנה מצבממש לפני הכתיבה, הכללים נבדקים שוב על נתונים עדכניים מה־Directory.אם העובד הושבת או קיבל כבר את ההרשאה בבקשה אחרת אחרי האישור, הביצוע נחסם.
Intake: יצירת Request IDה־ID נגזר מ־hash של תוכן הבקשה.הגשה חוזרת מזוהה אוטומטית כ־Replay.
LLM: מקומי או שירות APIGoogle Gemini API בלבד, בלי ספק חלופי. גם הבדיקות האוטומטיות רצות מול Gemini, ורק כשלים מודמים.חסר מפתח או ש־Gemini לא זמין? המערכת נעצרת בבטחה לפני כל פעולה.
Retrieve: ידע מקומיTF-IDF במקום Embeddings.חמישה מסמכים. שקוף, דטרמיניסטי ובלי תלויות.
Verify & Reportהדוח נוצר בפקודה נפרדת ומכסה את כל הריצות.מסמך מסירה אחד לכל התרחישים.
איןFAILED_SAFE מאפשר להריץ Execute שוב בלי אישור חדש.התקלה הייתה בתשתית ולא בתוכנית, וה־Idempotency מונע כפילות.

הפעולה דווחה כמוצלחת אבל לא נמצאה ב־Directory. לבדוק ידנית ולא להריץ שוב לפני הבדיקה.

python -m app reset

מגבלות ידועות

  • ה־Directory וה־Knowledge Base הם קבצים מקומיים שמדמים מערכות אמיתיות. בפרודקשן ה־Tools יקראו ל־API של IdP (Entra ID או Okta) ושל ITSM.
